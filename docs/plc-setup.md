# PLC との接続

アプリ内のサーバー（`src/SequenceDojo/PlcService.cs` と `Plc/`）が PLC と通信します。画面（WebView2）は直接 PLC と通信しません。

```
3D 作業盤（画面） ⇄ WebSocket ⇄ アプリ内サーバー ⇄ MELSEC（SLMP）/ KEYENCE（上位リンク）/ Modbus TCP ⇄ PLC・シミュレータ
```

## 対応している通信方式

| 通信方式 | 対象 | 使用ライブラリ | 既定ポート |
|---|---|---|---|
| 三菱 MELSEC（SLMP） | iQ-F（FX5）、iQ-R、iQ-L、MX-F、MX-R、Q、L（内蔵 Ethernet / Ethernet ユニット） | PlcComm.Slmp | 5000 |
| KEYENCE KV（上位リンク） | KV-NANO、KV-3000、KV-5000、KV-7000、KV-8000、KV-X500（各 XYM 表記あり） | PlcComm.KvHostLink | 8501 |
| Modbus TCP | Modbus TCP サーバー（スレーブ）として動く PLC・機器 | AMWD.Protocols.Modbus.Tcp | 502 |

機種の選択肢は、各ライブラリが対応している機種一覧から自動で作られます。

## 通信先 PLC と配線練習用 PLC

- **通信先 PLC**（接続タブ）: 実際に通信し、ラダープログラムを動かす PLC（実機またはシミュレータ）。
- **配線練習用 PLC**（配線タブ）: 3D で表示し、端子台との配線を練習する PLC の機種。

2 つは別々に指定できます。たとえば「配線練習は FX5S、通信先は iQ-R」「配線練習は FX5S、通信先は KV-8000」とできます。
入出力は並び順（1〜16 点目）で対応するので、通信先で使うデバイス番号は I/O モニタの「通信先」列で確認してください。

## 通信の中身

設定した周期（既定 30ms）ごとに、次の 2 つを繰り返します。

1. 盤の入力 16 点を「入力先頭」から連続 16 点に書き込む（値が変わったときだけ）
2. 「出力先頭」から連続 16 点を読み出し、盤の出力に反映する

接続時には、出力を 1 回読み出して応答を確かめてから「接続中」にします（UDP でも応答がなければ接続失敗）。
通信エラーが起きた場合は、1 秒待って自動で再試行します。

## 三菱 MELSEC（SLMP）

### PLC 側の設定（iQ-F / GX Works3 の例）

1. ナビゲーションの「パラメータ」→ CPU の「モジュールパラメータ」→「イーサネットポート」を開きます。
2. 「基本設定」で、PLC の IP アドレスを設定します。
3. 「相手機器接続構成設定」で **SLMP 接続機器** を追加し、プロトコル（TCP/UDP）と **ポート番号** を設定します。
4. パラメータを PLC に書き込み、PLC をリセット（または電源を入れ直し）します。
5. PC の IP アドレスを PLC と同じネットワークに設定し、`ping` で疎通を確認します。

機種によっては「RUN 中の書込み」を許可する設定があります。書込みでエラーになる場合は、その設定を確認してください。

### アプリ側の設定

| 項目 | 設定内容 |
|---|---|
| 通信方式 | 三菱 MELSEC（SLMP） |
| 機種 | 使用する PLC（FX5 は `MELSEC iQ-F`） |
| IP / ポート / 通信 | PLC の IP、手順 3 のポート番号と TCP / UDP |
| 入力先頭 / 出力先頭 | `X0` / `Y0`（iQ-F の X/Y は 8 進、その他は 16 進）。`M100` などの内部リレーも指定できます |

### GX Simulator 3

機種が **iQ-R / iQ-L** のときは「GX Simulator 3 に接続」をオンにできます。接続先は `127.0.0.1:5511`（TCP）に固定されます。
GX Works3 でシミュレーションを開始してから「接続」を押してください。

### 動作確認用の簡単なラダー（標準割付・iQ-F の場合）

| 動作 | 回路 |
|---|---|
| PB1 で PL1 点灯 | `X5` の a 接点 → `Y2` |
| SS1 入で右行 | `X12` の a 接点 → `Y1` |
| DSW の値を DPL1 に表示 | `X14`〜`X17` を `Y6`〜`Y11` に転送（BCD のまま） |

## KEYENCE KV（上位リンク）

### PLC 側の設定

KV STUDIO のユニットエディタで、CPU（または Ethernet ユニット）の **上位リンク** のポート番号（既定 8501）と IP アドレスを設定し、PLC に転送します。

### アプリ側の設定

| 項目 | 設定内容 |
|---|---|
| 通信方式 | KEYENCE KV（上位リンク） |
| 機種 | 使用する PLC。デバイスを X / Y / M 表記で使う場合は「（XYM）」の付いた機種 |
| IP / ポート / 通信 | PLC の IP、上位リンクのポート番号と TCP / UDP |
| 入力先頭 / 出力先頭 | 既定は `MR000` / `MR100`。`R000` / `R500` なども指定できます（XYM 表記の機種は `X0` / `Y0`） |

リレー（R / MR / LR / CR）はチャンネルとビットの番号です。16 点は `MR000`〜`MR015` のように並び、`R015` の次は `R100` になります。

### KV STUDIO シミュレータ

機種が **KV-8000 / KV-X500**（XYM 表記を含む）のときは「KV STUDIO シミュレータに接続」をオンにできます。接続先は `127.0.0.1:8501`（TCP）に固定されます。
KV STUDIO でシミュレータを起動し、上位リンク通信を開始してから「接続」を押してください。

## Modbus TCP

### アプリ側の設定

| 項目 | 設定内容 |
|---|---|
| 通信方式 | Modbus TCP |
| IP / ポート | 機器の IP と Modbus TCP のポート番号（既定 502） |
| Unit ID | 機器の Unit ID（0〜255、既定 1） |
| 入力先頭 | `C`（コイル 16 点）または `HR`（保持レジスタ 1 個の 16 ビット）。既定 `C0` |
| 出力先頭 | `C` / `DI`（16 点）または `HR` / `IR`（レジスタ 1 個の 16 ビット）。既定 `C16` |

- アドレスは **0 起点**です（`C0` は 1 番目のコイル。機器の資料で 00001 や 40001 と書かれる番地とは 1 ずれることがあります）。
- レジスタを指定した場合、1 点目がビット 0（最下位ビット）、16 点目がビット 15 です。I/O モニタには `HR1.0` のように表示します。
- `DI` と `IR` は読出し専用なので、入力先頭には指定できません。

## うまくつながらないとき

| 症状 | 確認すること |
|---|---|
| `接続失敗: … timed out` / `… deadline expired` | IP・ポート・TCP/UDP の一致、LAN ケーブル、PC 側 IP、ファイアウォール。シミュレータなら起動と通信開始 |
| `接続失敗` に機種やデバイスの説明が出る | 「機種」と「入力先頭」「出力先頭」の書式（例: `X0`、`MR000`、`C0`） |
| `通信エラー: …` が出て繰り返す | 通信途中で切断された。PLC の電源・ケーブル・他の機器とのポート競合 |
| 接続できるが盤が反応しない | ラダーのデバイス番号、PLC が RUN か、I/O モニタで入出力の変化を確認 |
| I/O モニタに「⚠ 配線に問題があります」 | 配線モードが ON で配線が足りない。配線タブで「配線チェック」、または配線モードを OFF |
| バッジが `サーバ切断` | アプリ内サーバーとの接続が切れた。アプリを起動し直す |

## 入力を X 以外に書き込む場合

「入力先頭」を内部リレー（MELSEC の `M100`、KEYENCE の `MR000` など）にすると、盤の入力 16 点をそこに書き込めます。
実機の入力（X や R）への書込みが入力リフレッシュで上書きされる環境では、この方法を使い、ラダー側で内部リレーを入力として使ってください。
ただし、検定本番のプログラムとはデバイス番号が変わる点に注意してください。
